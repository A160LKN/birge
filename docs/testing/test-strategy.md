# Тест-стратегия «Бірге»

## Цель

Убедиться, что команда видит одну и ту же доску и ничего не теряет: изменения коллег доходят до всех и вовремя, ничья правка не затирается молча, порядок карточек одинаков у всех, а чужие данные недоступны. Проверок больше всего там, где ошибка незаметна сразу, а вред от неё большой: реальное время, одновременные действия, фоновые задачи и права доступа.

## Анализ рисков

| Риск                                                             | Вероятность | Влияние | Как снижаем                                                                                                                          |
| ---------------------------------------------------------------- | ----------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Изменение не дошло до коллег — доска у всех разная               | средняя     | высокое | API-тесты WebSocket; E2E в двух браузерах одновременно; тест на обрыв соединения LISTEN; проверка на живом сайте после деплоя        |
| Две правки одной карточки — одна молча пропала                   | средняя     | высокое | оптимистическая блокировка по версии; API-тест `409`; компонентный тест экрана конфликта; E2E с двумя пользователями                 |
| После переподключения пропущены события                          | средняя     | высокое | догонялка по номеру последнего события; тесты «пропущенные события пересылаются» и «слишком много пропущено — перезагрузить доску»   |
| Порядок карточек расходится между клиентами и сервером           | средняя     | среднее | дробные ключи; общие тестовые векторы для Python и TypeScript; Hypothesis на сотнях случайных вставок; сортировка `COLLATE "C"` в БД |
| Одновременные переносы в одно место теряют карточку              | низкая      | высокое | интеграционный тест на PostgreSQL: параллельные переносы в один слот                                                                 |
| Посторонний видит или меняет чужую доску                         | низкая      | высокое | API-тесты прав на каждую сущность; чужая доска — `404`, а не `403`; удалённого участника отключает от сокета                         |
| Фоновая задача выполнилась дважды или потерялась                 | средняя     | среднее | 5 обработчиков на одной очереди — каждая задача ровно один раз; повторы с растущей паузой; подбор зависших задач                     |
| Опасный файл во вложении (исполняемый, HTML, «бомба» распаковки) | низкая      | высокое | проверка типа по содержимому, а не по расширению; защитные заголовки при скачивании; подписанные ссылки с истечением                 |
| CSV-выгрузка открывается в Excel как формула                     | низкая      | среднее | экранирование ячеек; юнит-тест на CSV-инъекцию                                                                                       |
| Вёрстка ломается на телефоне                                     | средняя     | среднее | E2E в профиле Pixel 7; ручной чек-лист на реальных устройствах                                                                       |

## Уровни тестирования

| Уровень                     | Что проверяем                                                                                             | Инструмент                                            | Сейчас        |
| --------------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | ------------- |
| Статический анализ          | ошибки до запуска, типы, совпадение типов фронтенда с OpenAPI бэкенда                                     | ruff, ESLint, TypeScript, Prettier                    | весь код      |
| Бэкенд: юнит                | чистая логика: ключи порядка, токены, подписи ссылок, проверка файлов, превью, CSV                        | pytest, Hypothesis                                    | 75            |
| Бэкенд: интеграционные      | то, что зависит от настоящей базы: очередь, транзакционность событий, сортировка, LISTEN/NOTIFY, миграции | pytest, PostgreSQL в CI                               | 17            |
| Бэкенд: API и WebSocket     | контракт HTTP и сокета, права, конфликты, файлы, выгрузка                                                 | pytest, httpx, тестовый клиент WebSocket              | 104           |
| Фронтенд: юнит и компоненты | применение событий, расчёт переноса, переподключение, экраны                                              | Vitest, Testing Library, MSW (включая моки WebSocket) | 83            |
| E2E                         | сценарии в браузере, в том числе два пользователя одновременно                                            | Playwright                                            | 12            |
| Смоук в Docker              | собранные образы поднимаются через `docker compose` и отвечают                                            | GitHub Actions                                        | каждый прогон |
| Ручное                      | внешний вид, удобство, реальные устройства, живой сайт после деплоя                                       | [чек-листы](checklists.md)                            | перед релизом |

Логику проверяют быстрые юнит-тесты, а E2E — только сценарии целиком, без перебора данных. Например, все случаи порядка карточек проверены юнит-тестами и Hypothesis, а в E2E — один перенос мышью у одного пользователя с проверкой у другого.

## Окружения

| Окружение                                             | Назначение                                                    |
| ----------------------------------------------------- | ------------------------------------------------------------- |
| Локально: Docker Compose (PostgreSQL)                 | разработка, отладка тестов                                    |
| GitHub Actions: Ubuntu 24.04, PostgreSQL 17, Chromium | автоматический прогон на каждое изменение                     |
| Render + Neon (бэкенд), Vercel (фронтенд)             | живой сайт: смоук после каждого деплоя                        |
| Устройства для ручной проверки                        | Chrome и Safari на macOS, Safari на iPhone, Chrome на Android |

Живой сайт отличается от CI: база Neon работает через пул соединений PgBouncer. Именно там нашёлся дефект с потерей уведомлений LISTEN, которого не было ни локально, ни в CI. Поэтому смоук на живом сайте обязателен после каждого изменения, связанного с базой или реальным временем.

## Тестовые данные

- Перед каждым бэкенд-тестом таблицы очищаются (`TRUNCATE … RESTART IDENTITY`): тесты независимы и не зависят от порядка.
- E2E создают пользователей и доски через API перед тестом, а не через интерфейс: так быстрее и стабильнее.
- Демо-данные (`python -m app.seed`): доска «Запуск Бірге», два пользователя, 8 карточек — для ручной проверки и демонстрации.

## Критерии

**Начало тестирования:** сборка проходит линтеры и проверку типов, миграции применяются.

**Готовность к релизу:**

- все автотесты в CI зелёные, покрытие бэкенда не ниже порога;
- смоук-чек-лист пройден на живом сайте в двух браузерах;
- нет открытых дефектов Critical и Major;
- найденные дефекты оформлены в [Issues](https://github.com/A160LKN/birge/issues?q=is%3Aissue) и закрыты тестом, который ловит их повтор.

## Дефекты

| Критичность | Определение                                          | Пример                                      |
| ----------- | ---------------------------------------------------- | ------------------------------------------- |
| Critical    | данные потеряны, разъехались между людьми или утекли | события не доходят до коллег на живом сайте |
| Major       | функция не работает, обходного пути нет              | `500` при удалении участника доски          |
| Minor       | работает, но с ошибкой или неудобством               | время в CSV по UTC вместо времени Астаны    |
| Trivial     | косметика                                            | подпись обрезается на узком экране          |

## Что не тестируется

- Нагрузка на тысячи одновременных пользователей — бесплатный хостинг, цель проекта другая. Корректность при одновременных действиях проверена интеграционными тестами.
- Браузеры старше двух последних версий.
- Восстановление после сбоя хостинга — это зона ответственности Render и Neon.
